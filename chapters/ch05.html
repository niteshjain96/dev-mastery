1 · Stating complexity without hedging

Question 1 What's the time and space complexity of your solution? Asked after every single problem · hedging here undoes a correct solution
Say this — the shape of a complete answer

"Time is O(n), because I make a single pass over the array and every operation inside the loop is constant. Space is O(k) where k is the number of distinct characters — bounded by 26 here, so effectively O(1) — because I only store the frequency map."

Three parts, always: the bound, the reason, and what n and any other variable actually refer to. Never say "I think it's probably O(n)". If two inputs matter, name both — O(n + m), not O(n).

// A  O(n²) → O(n)   — indexOf inside filter is a nested scan
const unique = (arr) => [...new Set(arr)];

// B  O(n²) → O(n)   — spreading the accumulator copies it every step
const groupByType = (widgets) => {
  const out = new Map();
  for (const w of widgets) {
    if (!out.has(w.type)) out.set(w.type, []);
    out.get(w.type).push(w);           // mutate the accumulator, don't rebuild it
  }
  return out;
};

// C  O(n²) → O(n)   — shift() re-indexes the whole array each time
function processQueue(queue) {
  for (let head = 0; head < queue.length; head++) run(queue[head]);
}

// D  O(n·m) → O(n + m)
const common = (a, b) => { const s = new Set(b); return a.filter((x) => s.has(x)); };

// E  O(n²) → O(n)   — splice shifts elements; filter or a write pointer does not
const removeInactive = (widgets) => widgets.filter((w) => w.active);
// in-place version, if the original array must be mutated:
function removeInactiveInPlace(widgets) {
  let write = 0;
  for (let read = 0; read < widgets.length; read++)
    if (widgets[read].active) widgets[write++] = widgets[read];
  widgets.length = write;              // truncate — setting length deletes the rest
  return widgets;
}

B is the one worth internalising, because it is idiomatic-looking modern JavaScript that is quietly quadratic. Every { ...acc } inside a reduce copies the whole accumulator. Reviewers love it; profilers hate it. E's in-place version is also your first read/write two-pointer, which is session 2.

Cross-questions

What does "amortised O(1)" mean?

Testing: do you use the word or understand it?

"That an individual operation may occasionally be expensive, but the average over a sequence is constant. push is the example: when the backing store is full the engine reallocates and copies, which is O(n), but it grows geometrically so that cost is spread across the next n pushes. So n pushes are O(n) total even though one of them was O(n)."

Is Map.get really O(1)?

Testing: precision about average versus worst case.

"O(1) average. It is a hash table, so a pathological set of colliding keys degrades it — in theory to O(n). In interview terms I state O(1) average and note the assumption. Engines also use insertion-ordered structures for Map, which is why iteration order is guaranteed and why it is slightly heavier than a plain object for small string-keyed data."

Object or Map for a frequency count?

Testing: a small, practical judgement they often probe.

"Map by default: any key type, guaranteed iteration order, a real size, no inherited keys, and no surprise when a key is called constructor or __proto__. A plain object is fine for known string keys and is marginally faster for small counts, but Object.create(null) is then worth it to avoid prototype keys. For character counts I often use a 26-slot array, which is fastest and makes the O(1) space claim obvious."

function twoSum(nums, target) {
  const seen = new Map();                  // value -> index

  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    if (seen.has(need)) return [seen.get(need), i];   // check BEFORE inserting
    seen.set(nums[i], i);
  }
  return [];                               // unreachable given the guarantee
}
// Time O(n) — one pass, O(1) map operations.
// Space O(n) — worst case every element is stored.

The one line that matters: check for the complement before inserting the current element. Insert first and twoSum([3, 3], 6) matches index 0 against itself and returns [0, 0]. That is the test case an interviewer adds after you say you are done, and handling it unprompted is worth more than the solution itself.

Things a strong candidate says here without being asked: "I return indices so I cannot sort the array — sorting would give me the two-pointer solution at O(n log n) and O(1) space, but it destroys the indices, so I'd have to store pairs. The hashmap is better here. If the array were sorted, two pointers would be the right answer because of the space."

Session 2 Two pointers ~75 min

3 · Two pointers from both ends

Question 3 Given a sorted array, find two numbers that sum to the target. O(1) space. The canonical opposite-ends problem · everything else in this family is a variation
Say this — the trigger and the invariant

Trigger: the array is sorted (or can be sorted), and I need a pair, triplet, or a comparison between the two ends. Sorted plus "find a pair" is almost always two pointers.

The invariant: start one pointer at each end. If the current sum is too small, the only way to increase it is to move the left pointer right. If it is too big, move the right pointer left. Each step eliminates one candidate permanently, so the whole search is one pass — O(n) time, O(1) space.

Say the elimination argument out loud. "Moving left inward discards every pair involving the old left element, and I know none of them can work because they are all even smaller." That is the proof of correctness, and offering it unprompted is what makes this answer strong rather than memorised.

Example — traced

nums = [2, 7, 11, 15, 19],  target = 26

 L              R     sum = 2 + 19 = 21   too small → L++
    L           R     sum = 7 + 19 = 26   found → [1, 4]

// and if the target were 20:
//   2+19=21 too big  → R--
//   2+15=17 too small→ L++
//   7+15=22 too big  → R--
//   7+11=18 too small→ L++   L === R → stop, not found
function twoSumSorted(nums, target) {
  let left = 0, right = nums.length - 1;

  while (left < right) {                     // strict: never pair an element with itself
    const sum = nums[left] + nums[right];
    if (sum === target) return [left, right];
    if (sum < target) left++;                // need bigger → only left can help
    else right--;                            // need smaller → only right can help
  }
  return [];
}
// Time O(n), Space O(1)

// 1 — valid palindrome, O(n) time, O(1) space
function isPalindrome(s) {
  const ok = (c) => /[a-z0-9]/i.test(c);
  let l = 0, r = s.length - 1;
  while (l < r) {
    while (l < r && !ok(s[l])) l++;              // skip junk, don't rebuild
    while (l < r && !ok(s[r])) r--;
    if (s[l].toLowerCase() !== s[r].toLowerCase()) return false;
    l++; r--;
  }
  return true;
}

// 2 — reverse vowels
function reverseVowels(s) {
  const V = new Set("aeiouAEIOU");
  const a = [...s];                              // strings are immutable
  let l = 0, r = a.length - 1;
  while (l < r) {
    if (!V.has(a[l])) { l++; continue; }
    if (!V.has(a[r])) { r--; continue; }
    [a[l], a[r]] = [a[r], a[l]];
    l++; r--;
  }
  return a.join("");
}

// 3 — container with most water
function maxArea(h) {
  let l = 0, r = h.length - 1, best = 0;
  while (l < r) {
    best = Math.max(best, (r - l) * Math.min(h[l], h[r]));
    // move the SHORTER side: the width can only shrink, so keeping the
    // shorter line can never produce a bigger area — it is dominated.
    if (h[l] < h[r]) l++; else r--;
  }
  return best;
}

// 4 — three sum, O(n²) time, O(1) extra space beyond the output
function threeSum(nums) {
  nums.sort((a, b) => a - b);                    // numeric comparator — see Ch6
  const out = [];

  for (let i = 0; i < nums.length - 2; i++) {
    if (nums[i] > 0) break;                      // sorted: no triplet can reach 0
    if (i > 0 && nums[i] === nums[i - 1]) continue;   // skip duplicate anchors

    let l = i + 1, r = nums.length - 1;
    while (l < r) {
      const sum = nums[i] + nums[l] + nums[r];
      if (sum === 0) {
        out.push([nums[i], nums[l], nums[r]]);
        while (l < r && nums[l] === nums[l + 1]) l++;  // skip duplicate pairs
        while (l < r && nums[r] === nums[r - 1]) r--;
        l++; r--;
      } else if (sum < 0) l++;
      else r--;
    }
  }
  return out;
}

// 5 — sort colors / Dutch national flag, one pass
function sortColors(nums) {
  let low = 0, mid = 0, high = nums.length - 1;
  while (mid <= high) {
    if (nums[mid] === 0) { [nums[low], nums[mid]] = [nums[mid], nums[low]]; low++; mid++; }
    else if (nums[mid] === 2) { [nums[mid], nums[high]] = [nums[high], nums[mid]]; high--; }
    // do NOT advance mid here — the value swapped in from `high` is unexamined
    else mid++;
  }
  return nums;
}

Problem 3 is the one to be able to argue. "Move the shorter side" needs a justification, not an assertion: the area is limited by the shorter line, and moving the taller one inward can only reduce the width while the height stays capped by the same short line — so every pair involving the shorter line is already dominated by the one we just measured. Interviewers ask "why is that safe?" and a shrug undoes the solution.

Problem 5's subtlety is not advancing mid after swapping with high, because the incoming value has not been classified yet. Get that wrong and it fails on [2,0,1]. Say it out loud as you write it.

4 · Read and write pointers

Question 4 Remove duplicates from a sorted array in place, and return the new length. The canonical same-direction problem · in-place is the point
Say this — the trigger and the invariant

Trigger: remove, filter, partition or compact in place, with O(1) extra space. Also any problem where a fast pointer explores and a slow pointer marks a boundary.

The invariant: two pointers move in the same direction at different speeds. read scans every element; write marks the end of the region that is already correct. Everything before write is the answer; everything from read onward is unexamined. You only copy when the element qualifies.

Saying "everything left of write is finished" is the whole technique. Once you can state the invariant, the code writes itself and you stop making off-by-one errors. 

function removeDuplicates(nums) {
  if (nums.length === 0) return 0;
  let write = 1;                              // nums[0] is trivially kept

  for (let read = 1; read < nums.length; read++) {
    if (nums[read] !== nums[write - 1]) {     // compare to the last KEPT value
      nums[write] = nums[read];
      write++;
    }
  }
  return write;                               // nums[0..write-1] is the answer
}
// Time O(n), Space O(1)

// 1 — move zeroes: write pointer marks the end of the non-zero prefix
function moveZeroes(nums) {
  let write = 0;
  for (let read = 0; read < nums.length; read++)
    if (nums[read] !== 0) nums[write++] = nums[read];
  while (write < nums.length) nums[write++] = 0;
  return nums;
}

// 2 — remove element; order-free version swaps from the end,
// doing O(k) writes instead of O(n) when matches are rare
function removeElement(nums, val) {
  let n = nums.length, i = 0;
  while (i < n) {
    if (nums[i] === val) nums[i] = nums[--n];   // pull the last element in
    else i++;
  }
  return n;
}

// 3 — merge from the BACK, so we never overwrite unread elements of `a`
function merge(a, m, b, n) {
  let i = m - 1, j = n - 1, write = m + n - 1;
  while (j >= 0) {
    a[write--] = (i >= 0 && a[i] > b[j]) ? a[i--] : b[j--];
  }
  return a;
}

// 4 — at most twice: compare against write - 2 instead of write - 1
function removeDuplicatesII(nums) {
  let write = 0;
  for (const x of nums) {
    if (write < 2 || x !== nums[write - 2]) nums[write++] = x;
  }
  return write;
}

const applyBackspaces = (s) => {

// 5b — O(1) space, scanning from the back with skip counters
function backspaceCompare(s, t) {
  let i = s.length - 1, j = t.length - 1;

  const nextValid = (str, k) => {
    let skip = 0;
    while (k >= 0) {
      if (str[k] === "#") { skip++; k--; }
      else if (skip > 0) { skip--; k--; }
      else break;                              // k is a surviving character
    }
    return k;
  };

  while (true) {
    i = nextValid(s, i);
    j = nextValid(t, j);
    if (i < 0 && j < 0) return true;           // both exhausted together
    if (i < 0 || j < 0) return false;           // one ran out first
    if (s[i] !== t[j]) return false;
    i--; j--;
  }
}

Problem 3's "fill from the back" is a transferable idea, not a trick: when an in-place merge would overwrite data you still need, reverse the direction so you always write into space that is already dead. Say that as a principle and it will serve you in other problems.

Problem 4 is the one to notice. Going from "at most once" to "at most twice" is a single index change, write - 1 to write - 2, plus the write < 2 guard. Generalising to "at most k" is the same code with write - k. Spotting that generalisation out loud is a strong signal; an interviewer will often ask for it directly.

5 · Fixed-size windows

Question 5 Find the maximum sum of any contiguous subarray of size k. The canonical fixed window · usually a warm-up before the variable version
Say this — the trigger and the invariant

Trigger: the words contiguous, subarray or substring, plus a fixed length k. Contiguity is the signal — if the elements need not be adjacent, this is not a window problem.

The invariant: instead of recomputing each window from scratch, which is O(n·k), maintain a running aggregate. Each step adds the incoming element and removes the outgoing one, so every window costs O(1) and the whole scan is O(n).

State the brute force first — nested loops, O(n·k) — then say "but consecutive windows share k−1 elements, so recomputing the overlap is wasted work." That sentence is the sliding window insight, and saying it shows you derived the technique rather than recalled it. 

function maxSumSubarray(nums, k) {
  if (nums.length < k) return null;

  let sum = 0;
  for (let i = 0; i < k; i++) sum += nums[i];     // build the first window
  let best = sum;

  for (let end = k; end < nums.length; end++) {
    sum += nums[end] - nums[end - k];             // add incoming, drop outgoing
    best = Math.max(best, sum);
  }
  return best;
}
// Time O(n), Space O(1)

// 2 — find all anagrams, with an O(1) match check via a `matches` counter
function findAnagrams(s, p) {
  if (p.length > s.length) return [];
  const need = new Array(26).fill(0);
  const win  = new Array(26).fill(0);
  const idx  = (c) => c.charCodeAt(0) - 97;

  for (const c of p) need[idx(c)]++;

  // how many of the 26 letters currently have the exact right count
  let matches = 0;
  for (let i = 0; i < 26; i++) if (need[i] === 0) matches++;

  const out = [];
  for (let end = 0; end < s.length; end++) {
    const inC = idx(s[end]);
    win[inC]++;
    if (win[inC] === need[inC]) matches++;
    else if (win[inC] === need[inC] + 1) matches--;   // just went over

    if (end >= p.length) {
      const outC = idx(s[end - p.length]);
      win[outC]--;
      if (win[outC] === need[outC]) matches++;
      else if (win[outC] === need[outC] - 1) matches--;  // just went under
    }

    if (matches === 26) out.push(end - p.length + 1);   // O(1) check
  }
  return out;
}

// 4 — maximum vowels, the minimal window
function maxVowels(s, k) {
  const V = new Set("aeiou");
  let count = 0;
  for (let i = 0; i < k; i++) if (V.has(s[i])) count++;
  let best = count;
  for (let end = k; end < s.length; end++) {
    if (V.has(s[end])) count++;
    if (V.has(s[end - k])) count--;

  return best;
}

Question 6 Length of the longest substring without repeating characters. One of the most-asked medium problems in frontend interviews
Say this — the trigger and the template

Trigger: "longest" or "shortest" contiguous run subject to a constraint, with no fixed length given.

The template, and it is the same every time: expand the window by moving end forward one step at a time. After each expansion, while the window violates the constraint, shrink from start. Then record the answer. Every element enters the window once and leaves at most once, so despite the nested loop it is O(n), not O(n²) — say that explicitly, because the nested while makes interviewers ask.

The only thing that changes between problems is what makes the window invalid and what you record. Learn the skeleton once.

function minWindow(s, t) {
  if (t.length > s.length) return "";
  const need = new Map();
  for (const c of t) need.set(c, (need.get(c) ?? 0) + 1);

  let required = need.size;                  // distinct chars still unsatisfied
  let start = 0, bestLen = Infinity, bestStart = 0;
  const win = new Map();

  for (let end = 0; end < s.length; end++) {
    const c = s[end];
    win.set(c, (win.get(c) ?? 0) + 1);
    if (need.has(c) && win.get(c) === need.get(c)) required--;

    while (required === 0) {                 // valid → try to shrink
      if (end - start + 1 < bestLen) { bestLen = end - start + 1; bestStart = start; }
      const d = s[start];
      win.set(d, win.get(d) - 1);
      if (need.has(d) && win.get(d) < need.get(d)) required++;   // broke it
      start++;
    }
  }
  return bestLen === Infinity ? "" : s.slice(bestStart, bestStart + bestLen);
}

Two structural points worth saying out loud. When the answer is a maximum, you shrink only while the window is invalid and record after the shrink. When the answer is a minimum, you shrink while the window is still valid and record inside the shrink loop. Getting those two shapes straight removes most of the difficulty from this family.

Problem 2's non-decreasing maxFreq is the famous subtlety. It looks like a bug: after shrinking, the real maximum frequency may be lower, and we never reduce it. It is correct anyway, because a stale-high maxFreq can only make the window look more valid than it is, so the window never shrinks below the best length already found — and we only ever report lengths that were genuinely achieved. Recomputing it each step would also be correct but costs O(26) per step. If an interviewer challenges it, that two-sentence argument is the answer; if you are not confident, recompute and say why you chose safety.

// version A — sorted key, O(n · k log k). Say this first, it is fine.
function groupAnagrams(words) {
  const groups = new Map();
  for (const w of words) {
    const key = [...w].sort().join("");
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key).push(w);
  }
  return [...groups.values()];
}

// version B — count signature, O(n · k). Offer this as the improvement.
function groupAnagramsFast(words) {

    const counts = new Array(26).fill(0);
    for (const c of w) counts[c.charCodeAt(0) - 97]++;

}

// 1 — valid anagram, single map, one pass each way
function isAnagram(s, t) {
  if (s.length !== t.length) return false;       // cheap early exit
  const count = new Map();
  for (const c of s) count.set(c, (count.get(c) ?? 0) + 1);
  for (const c of t) {
    const n = count.get(c);
    if (!n) return false;                        // absent or already exhausted
    count.set(c, n - 1);
  }
  return true;                                   // lengths matched, so no leftovers
}

// 2 — top k frequent, bucket sort: O(n) time and space
function topKFrequent(nums, k) {
  const count = new Map();
  for (const n of nums) count.set(n, (count.get(n) ?? 0) + 1);

  // a frequency can be at most nums.length, so index buckets by count
  const buckets = Array.from({ length: nums.length + 1 }, () => []);
  for (const [value, freq] of count) buckets[freq].push(value);

  const out = [];
  for (let f = buckets.length - 1; f >= 0 && out.length < k; f--) {
    for (const v of buckets[f]) {
      out.push(v);
      if (out.length === k) break;
    }
  }
  return out;
}

// 4 — isomorphic strings: the mapping must be a BIJECTION
function isIsomorphic(s, t) {
  if (s.length !== t.length) return false;
  const sToT = new Map(), tToS = new Map();

  for (let i = 0; i < s.length; i++) {
    const a = s[i], b = t[i];
    if (sToT.has(a) && sToT.get(a) !== b) return false;
    if (tToS.has(b) && tToS.get(b) !== a) return false;   // the reverse check
    sToT.set(a, b);
    tToS.set(b, a);
  }
  return true;
}

Problem 2's bucket sort is the insight to keep. When the values you are sorting by are bounded small integers — here a frequency, which cannot exceed n — you can index an array by them instead of comparing. That turns O(n log n) into O(n). It is the same idea as counting sort and it comes up whenever a problem says "k most frequent" or "sort by count".

Problem 4 is the one people get wrong. A single map accepts "badc"/"baba", because nothing stops two different source characters mapping to the same target. Problem 3's two passes are better than one because a single pass cannot know a character is unique until the string ends. Some candidates try to track candidates in one pass with an ordered structure; it works but is more code for the same O(n). Question 8 Count the subarrays whose sum equals k. The array can contain negatives. Common medium · the negatives clause is there to rule out sliding window
Say this — the trigger and the derivation

Trigger: contiguous subarray sum with an exact target, and negative numbers allowed. Negatives kill the sliding window, because removing an element can increase the sum — so there is no monotonic shrink condition.

The derivation, and say it in this order: let prefix[i] be the sum of everything up to index i. The sum of the subarray from j+1 to i is prefix[i] − prefix[j]. I want that to equal k, so prefix[j] = prefix[i] − k. So as I scan, I ask: how many earlier prefixes had exactly that value? A hashmap of prefix sum to count answers it in O(1), giving one pass overall.

The seed map.set(0, 1) is essential — it represents the empty prefix, which is what makes subarrays starting at index 0 count. 

function subarraySum(nums, k) {
  const counts = new Map([[0, 1]]);          // empty prefix — handles arrays
  let prefix = 0, total = 0;                 // that start at index 0

  for (const n of nums) {
    prefix += n;
    total += counts.get(prefix - k) ?? 0;    // count BEFORE inserting
    counts.set(prefix, (counts.get(prefix) ?? 0) + 1);
  }
  return total;
}
// Time O(n), Space O(n)

function productExceptSelf(nums) {

  let prefix = 1;
  for (let i = 0; i < nums.length; i++) {    // left pass: product of everything before i
    out[i] = prefix;
    prefix *= nums[i];
  }

  let suffix = 1;
  for (let i = nums.length - 1; i >= 0; i--) {  // right pass: multiply in what's after

    suffix *= nums[i];
  }
  return out;
}

Problem 2 is the one to be able to justify. The loop looks quadratic — a while inside a for — and it is not, because the if (set.has(n - 1)) continue guard means only the smallest element of each run ever enters the while. Every element is visited at most twice overall: once by the outer loop, once by the walk of its own sequence. Interviewers ask "isn't that O(n²)?" and that is the answer.

Problem 4's modulo is a genuine JavaScript trap. -1 % 5 is -1, not 4, because % is remainder, not modulo, and takes the sign of the dividend. Without the ((x % k) + k) % k normalisation, negative prefixes land in different buckets from the positive ones they should match. It is a one-line fix that fails silently on positive-only test data.

function isValid(s) {

// 2 — reverse Polish notation
function evalRPN(tokens) {
  const stack = [];
  const ops = {
    "+": (a, b) => a + b,
    "-": (a, b) => a - b,
    "*": (a, b) => a * b,
    "/": (a, b) => Math.trunc(a / b),        // trunc, NOT floor: -7/2 is -3
  };

  for (const t of tokens) {
    if (t in ops) {
      const b = stack.pop(), a = stack.pop();  // order matters: second pop is LEFT
      stack.push(ops[t](a, b));
    } else {
      stack.push(Number(t));
    }
  }
  return stack.pop();
}

// 3 — decode string
function decodeString(s) {
  const countStack = [];
  const strStack = [];
  let current = "";
  let count = 0;

  for (const c of s) {
    if (c >= "0" && c <= "9") {
      count = count * 10 + Number(c);        // multi-digit: "12[a]"
    } else if (c === "[") {
      countStack.push(count);                // save the context and start fresh
      strStack.push(current);
      count = 0;
      current = "";
    } else if (c === "]") {
      const repeat = countStack.pop();
      const previous = strStack.pop();
      current = previous + current.repeat(repeat);   // restore and append
    } else {
      current += c;
    }
  }
  return current;
}

// 4 — remove adjacent duplicates
function removeDuplicates(s) {
  const stack = [];
  for (const c of s) {
    if (stack.at(-1) === c) stack.pop();
    else stack.push(c);
  }
  return stack.join("");
}

// 5 — simplify path
function simplifyPath(path) {
  const stack = [];
  for (const part of path.split("/")) {
    if (part === "" || part === ".") continue;     // "" from // and trailing /
    if (part === "..") stack.pop();                // pop on empty is a safe no-op
    else stack.push(part);
  }
  return "/" + stack.join("/");
}

10 · Monotonic stacks

Question 10 For each day, how many days until a warmer temperature? The canonical monotonic stack · recognising the pattern is the whole battle
Say this — the trigger and the invariant

Trigger: "next greater", "next smaller", "previous greater", "how far until", "how many are visible", or any problem where each element needs to find its nearest neighbour satisfying a comparison. If the brute force is "for each element, scan forward until I find something bigger", it is a monotonic stack.

The invariant: keep a stack of indices whose values are in monotonic order — decreasing if you are looking for the next greater element. When a new element arrives that breaks the order, it is the answer for everything you pop. Each index is pushed once and popped at most once, so the whole thing is O(n) despite the inner loop.

Store indices, not values. You almost always need the distance or the position, and you can always read the value back. 

function dailyTemperatures(temps) {
  const answer = new Array(temps.length).fill(0);
  const stack = [];                          // indices, decreasing temperature

  for (let i = 0; i < temps.length; i++) {
    // today is warmer than everything at the top → resolve those days
    while (stack.length && temps[i] > temps[stack.at(-1)]) {
      const day = stack.pop();
      answer[day] = i - day;
    }
    stack.push(i);
  }
  return answer;                             // anything still on the stack stays 0
}
// Time O(n) — each index pushed once, popped once. Space O(n).

// 1 — next greater element I
function nextGreaterElement(nums1, nums2) {

// 2 — circular: walk twice, push only on the first lap
function nextGreaterElements(nums) {
  const n = nums.length;
  const answer = new Array(n).fill(-1);
  const stack = [];
  for (let i = 0; i < 2 * n; i++) {
    const idx = i % n;
    while (stack.length && nums[idx] > nums[stack.at(-1)]) answer[stack.pop()] = nums[idx];
    if (i < n) stack.push(idx);              // second lap only resolves
  }
  return answer;
}

// 3 — trapping rain water, two pointers: O(n) time, O(1) space.
// Water above a bar = min(tallest to its left, tallest to its right) - its height.
function trap(height) {
  let l = 0, r = height.length - 1;
  let leftMax = 0, rightMax = 0, total = 0;

  while (l < r) {
    if (height[l] < height[r]) {
      // the left bar is the smaller side, so leftMax alone decides the
      // water here — we know SOME bar on the right is at least as tall
      leftMax = Math.max(leftMax, height[l]);
      total += leftMax - height[l];
      l++;
    } else {
      rightMax = Math.max(rightMax, height[r]);
      total += rightMax - height[r];
      r--;
    }
  }
  return total;
}

// 4 — largest rectangle in histogram
function largestRectangleArea(heights) {
  const stack = [];                          // indices, increasing height
  let best = 0;

  // the trailing 0 forces every remaining bar to be resolved
  for (let i = 0; i <= heights.length; i++) {
    const h = i === heights.length ? 0 : heights[i];

    while (stack.length && h < heights[stack.at(-1)]) {
      const height = heights[stack.pop()];
      // the rectangle extends from just after the new stack top,
      // to just before i — because those are the first shorter bars
      // on each side
      const left = stack.length ? stack.at(-1) + 1 : 0;
      const width = i - left;
      best = Math.max(best, height * width);
    }
    stack.push(i);
  }
  return best;
}

Problem 3's two-pointer argument is the part to rehearse. The water above a bar is min(maxLeft, maxRight) − height. The two-pointer version works because whenever height[l] < height[r], we know there exists some bar on the right at least as tall as height[r], hence at least as tall as height[l] — so the right side cannot be the limiting factor and leftMax alone determines the answer at l. State that and the code is obvious; skip it and the code looks like magic.

Problem 4's two tricks: the sentinel zero at the end, which forces the stack to drain without duplicating the resolution logic; and the width calculation, where the left boundary is the element after the new stack top because that top is the nearest shorter bar on the left. Getting the width right is the entire difficulty. If you can only remember one thing: the popped bar's rectangle spans from just past the new top to just before the current index.

Question 11 Reverse a string. Now handle emoji. The reversal is a warm-up; the emoji follow-up is a real differentiator
Say this

JavaScript strings are immutable and are sequences of UTF-16 code units, not characters. Indexing and length operate on code units, so any character outside the Basic Multilingual Plane — emoji, many CJK extensions, mathematical symbols — is stored as a surrogate pair of two code units and is silently split by index-based operations.

So s.split("").reverse().join("") corrupts emoji. [...s] and for…of iterate by code point, which fixes surrogate pairs — but still not grapheme clusters like a flag, a skin-tone modifier or a combining accent, which are several code points that render as one character. Fully correct segmentation needs Intl.Segmenter.

Saying those three levels — code unit, code point, grapheme cluster — is the complete answer, and almost nobody gives it.

// 2 — string compression
function compress(s) {
  const out = [];                            // array + join, never += in a loop
  let i = 0;
  while (i < s.length) {
    const c = s[i];
    let run = 0;
    while (i < s.length && s[i] === c) { run++; i++; }
    out.push(c, run);
  }
  const compressed = out.join("");
  return compressed.length < s.length ? compressed : s;
}

// 3 — longest common prefix, vertical scan: O(n · m) worst, often much less
function longestCommonPrefix(strs) {
  if (strs.length === 0) return "";
  for (let i = 0; i < strs[0].length; i++) {
    const c = strs[0][i];
    for (const s of strs) {
      if (i === s.length || s[i] !== c) return strs[0].slice(0, i);
    }
  }
  return strs[0];
}

// 4 — roman to integer
function romanToInt(s) {
  const V = { I: 1, V: 5, X: 10, L: 50, C: 100, D: 500, M: 1000 };
  let total = 0;
  for (let i = 0; i < s.length; i++) {
    // a smaller numeral before a larger one means subtract
    if (V[s[i]] < V[s[i + 1]]) total -= V[s[i]];
    else total += V[s[i]];
  }
  return total;
}

// 5 — longest palindromic substring, expand around 2n-1 centres
function longestPalindrome(s) {
  let bestStart = 0, bestLen = 0;

  const expand = (l, r) => {
    while (l >= 0 && r < s.length && s[l] === s[r]) { l--; r++; }
    const len = r - l - 1;                   // the loop overshoots by one each side
    if (len > bestLen) { bestLen = len; bestStart = l + 1; }
  };

  for (let i = 0; i < s.length; i++) {
    expand(i, i);                            // odd length, centred on a character
    expand(i, i + 1);                        // even length, centred between two
  }
  return s.slice(bestStart, bestStart + bestLen);
}
// Time O(n²), Space O(1). Manacher's is O(n) — mention it, don't write it.

Problem 4's lookahead is safe because s[i + 1] is undefined at the end and V[undefined] is undefined, and any number compared with undefined is false — so the last numeral always adds. That is one of the rare cases where JavaScript's loose comparison behaviour works in your favour, and it is worth noticing rather than adding a bounds check.

Problem 5's r - l - 1 is the only tricky line: the while exits one step past the valid range on both sides, so the true length is (r - 1) - (l + 1) + 1. Derive it on paper once and you will not get it wrong again.

On problem 3, say why you would not sort: sorting the array and comparing only the first and last strings is a clever O(n log n · m) trick, but vertical scanning is O(n · m) and clearer. Reaching for the clever one when the simple one is asymptotically better is a bad instinct to display.

// 3 — PATTERN: variable sliding window with a count map ("at most k distinct").
function longestTwoDistinct(nums) {
  const count = new Map();
  let start = 0, best = 0;
  for (let end = 0; end < nums.length; end++) {
    count.set(nums[end], (count.get(nums[end]) ?? 0) + 1);
    while (count.size > 2) {
      const c = nums[start];
      count.set(c, count.get(c) - 1);
      if (count.get(c) === 0) count.delete(c);
      start++;

    best = Math.max(best, end - start + 1);

  return best;

// 4 — PATTERN: sort, then a single merge pass. Not a hashmap problem.
function mergeIntervals(intervals) {
  if (intervals.length === 0) return [];
  intervals.sort((a, b) => a[0] - b[0]);     // numeric comparator, always

  const out = [intervals[0].slice()];
  for (let i = 1; i < intervals.length; i++) {
    const last = out.at(-1);
    if (intervals[i][0] <= last[1]) last[1] = Math.max(last[1], intervals[i][1]);
    else out.push(intervals[i].slice());
  }
  return out;
}

// 5 — PATTERN: Boyer-Moore voting. Not a hashmap — the O(1) space
// constraint rules that out and is the hint.
function majorityElement(nums) {
  let candidate = null, count = 0;
  for (const n of nums) {
    if (count === 0) candidate = n;
    count += (n === candidate) ? 1 : -1;
  }
  return candidate;   // valid only because a majority is guaranteed to exist
}

Three levels of string length?

Code units (.length), code points ([...s]), grapheme clusters (Intl.Segmenter).

How many centres does "expand around centre" need?

2n−1 — every character, plus every gap between two characters for even-length palindromes.

Sorting strings for a UI — what do you use?

Intl.Collator, created once and reused. Raw < uses code unit order and gets case and accents wrong.

"Find the majority element in O(1) space" — what is the constraint telling you?

No hashmap. It is Boyer-Moore voting.
